## 1. WHAT WE ARE BUILDING

A **white-label CRM for home-tuition bureaus** (businesses that connect parents/students with home tutors).

Workflow:

1. A parent fills a **Student Requirement form** on the bureau website.
2. A tutor fills a **Tutor Registration form** on the bureau website.
3. Both are saved to the client's **Google Sheet**.
4. The bureau owner logs into a private **Admin Dashboard**.
5. The owner searches tutors, uses **Tutor Finder** (smart matching) to find the best tutors for a student, contacts them via WhatsApp, records the assignment, the demo class, follow-ups and (optionally) payments.

**We are NOT building:** teacher login, student login, online classroom, attendance, homework, exams, timetable, payroll, or a school management system. It is an **admin-only** tool.

**One codebase, many clients.** Each client gets their own deployment, their own Google Sheet, their own passwords, their own branding. Data of different clients must never mix.

Example clients: C.B. Jha Tutorials, Aman Home Tuition Bureau, Swati Home Tuition Bureau, Ayush Anand Home Tuition Bureau.

## 6. GOOGLE SHEET DESIGN

### 6.1 General rules (apply to every tab)

- **Row 1 = headers. Data starts at row 2.** Column A is used (no blank leading column).
- **All KPIs and counts are computed by the app, never by sheet formulas.** Do not put formulas in data tabs.
- **Find columns by header name, never by position.** Build a map `headerName → columnIndex` on read. Extra columns are ignored. Reordered columns still work.
- **Header health check:** before any read/write on a tab, verify all required headers exist. If any is missing/renamed → refuse writes to that tab, show a clear red banner to the admin ("Tutors tab is missing column: phone"), and log it. Also run it from `npm run check-sheet` and show status on the Settings page.
- **Never identify a record by row number.** Always by its ID. Right before an update, re-find the row by ID in the ID column.
- **Write with `valueInputOption: RAW`.** Never `USER_ENTERED` (otherwise Sheets may turn `+9198...` or `=...` into numbers/formulas). Set plain-text format on phone, ID, postal code and date columns.
- **Multi-value fields** (subjects, classes, boards, localities, timings, days, file IDs) are stored as text separated by `|` — e.g. `Maths|Physics`. Values come from `Lookups` (never free text typed differently each time). Provide `splitMulti()` / `joinMulti()` helpers; use them everywhere.
- **Empty values** are stored as an empty cell, never as `null`, `N/A`, `-`, or `undefined`.
- **Booleans** are `TRUE` / `FALSE` text. `archived` default `FALSE`.
- **Dates/times** are stored as **ISO 8601 in UTC**, e.g. `2026-11-07T14:30:00Z`. Date-only fields (`dob`, `start_date`, `end_date`) are `YYYY-MM-DD`. Always display in the client's timezone (default Asia/Kolkata).
- **Archive, don't delete.** `archived=TRUE` hides a record from normal lists. Only the "anonymize" action (Section 24) removes personal data.
- **Optimistic concurrency:** edit forms load the record's `updated_at`. On save, the server compares it with the sheet's current `updated_at`; if different → reject with "This record was changed by someone else. Reload and try again."
- **The owner may edit the sheet by hand.** Don't crash on odd values: validate on read, show unknown/invalid values as-is with a small warning icon.
- **Protect the sheet:** the template should protect the header row and have data validation (dropdowns) on status columns. Only the service account and the owner have access.

### 6.3 Reliability rules for Google Sheets

Google Sheets is **not** a real database. Because of that:

- **Batch reads:** read a whole tab with one `values.get`. Never one request per row.
- **Caching:** cache reads for ~30 seconds (Redis if configured, otherwise in memory); clear the cache for that tab after every successful write. **Never use cached data** for verification, assignment creation, or any action that depends on current status: read fresh.
- **Write lock:** all writes go through one function. If Redis is configured, it takes a short lock per spreadsheet (`SET key NX PX 10000`) so two simultaneous writes don't collide. Without Redis, new rows still use Sheets append (safe for simultaneous adds) and updates rely on the `updated_at` check, so a collision shows an error instead of silently overwriting.
- **Retries:** on HTTP 429 or 5xx, retry up to 4 times with exponential backoff (1s, 2s, 4s, 8s). Request timeout 10 seconds. After that, return a clear error — never pretend success.
- **Multi-tab writes** (e.g. create record + ActivityLog): write the main record first; it is the source of truth. If the ActivityLog write fails, retry; if it still fails, log the failure to server logs and continue — but never lose the main record.
- **Quota protection:** public forms are rate-limited (Section 10.4) so spam cannot use up the Google quota and break the dashboard.
- **Honest limits:** filtering/search/pagination happen in memory after the batch read. This is fine up to about 10,000 rows per tab. If a tab passes 10,000 rows or reads take over 3 seconds, show a warning on the Settings page: "Consider migrating to a database."

### 7.4 IDs

- Every record has a permanent ID, **never changed**, never based on row number.
- Format: `PREFIX-YYMM-XXXX` where XXXX is 4 random characters from `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (no confusing 0/O/1/I). Examples: `STU-2611-K7QX`, `TUT-2611-9MPA`, `ASN-…`, `FUP-…`, `PAY-…`, `ACT-…`.
- Before saving, check the new ID does not already exist; if it does, generate another.
- Do not use sequential counters (they cause collisions).

### 7.5 Phone numbers

- Normalize every phone to **E.164 text**, e.g. `+919876543210`. If the user types 10 digits, add the client's default country code. Accept spaces, dashes, `0` prefix; reject anything else.
- Indian default rule: 10 digits, starting with 6, 7, 8 or 9. (Other countries: only check length 8–15 digits.)
- Store as text. If `whatsapp` is empty, treat it as equal to `phone`.
- For `wa.me` links use digits only (no `+`, no spaces): `https://wa.me/919876543210?text=<URL-encoded message>`.

- `enabled` — shown or not

## 9. VALIDATION & DUPLICATES (SHARED BY EVERYTHING)

**One validation layer:** Zod schemas in `lib/validation`. The same schemas are used by public forms, quick add, edit forms and API routes. The server **always** re-validates; never trust the browser.

General rules: trim text; max lengths (names 100, long text 1000, notes 2000); reject unknown fields; budget/fee must be numbers ≥ 0; years 0–60; email format; URLs must start with `https://`; multi-select values must exist in `Lookups` (active).

**Student duplicate check** (on create): same normalized `phone` + same `student_name` (case-insensitive) + same `class`, created within `duplicate_window_days` (default 30).
- Public form: still save the record, set `duplicate_of` = the earlier student_id, and flag it for the admin. Show the parent the normal success screen (don't reveal other records).
- Quick add (admin): show a warning with a link to the existing record; admin can "Save anyway".

**Tutor duplicate check:** same normalized `phone` **or** same `email` (if given).
- Public form: do **not** create a second record. Show a friendly message: "You are already registered with us. Our team will contact you." (Never reveal any details of the existing record.)
- Quick add (admin): warn and link to the existing tutor; admin can "Save anyway".

**Idempotency:** every public form generates a random `submission_key` (UUID) when the page loads and sends it with the submit. If a record with that key already exists, return the earlier success instead of creating another (handles double-taps and retries).

## 11. ADMIN AUTHENTICATION & SECURITY

### 11.1 Login

- One owner account: username from `ADMIN_USERNAME`, password verified against `ADMIN_PASSWORD_HASH` (bcrypt). **Never** store passwords in Google Sheets or code.
- `npm run hash-password` prompts for a password and prints a hash to paste into env.
- On success set a **signed, HTTP-only, Secure, SameSite=Lax cookie** (use `jose` for a signed token). Session lasts 7 days; logout clears it.
- **Login rate limit:** 5 failed attempts per 15 minutes per IP → temporary block (Redis if configured, otherwise in-memory per instance). Use a constant generic error ("Invalid username or password").
- Changing the password = generate new hash, update env var, redeploy. Document this in `docs/ADMIN-GUIDE.md`. Add a "Change password" instruction only; no email reset flow in v1.

### 11.2 Authorization

- **Every** `/api/admin/*` route and every dashboard server component checks the session itself. Do **not** rely on Next.js middleware alone. Keep Next.js updated to a patched version.
- State-changing requests: require POST/PATCH/DELETE with a same-origin check (`Origin` header must match the app URL) in addition to SameSite cookies.
- Public routes and admin routes live in separate folders so mistakes are obvious.

### 11.3 General security checklist

Input validation (Zod) everywhere; React escapes output (never use `dangerouslySetInnerHTML` with user data); CSV exports must neutralize formulas (prefix cells starting with `=`, `+`, `-`, `@` with `'`); security headers (CSP, `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`); errors shown to users are friendly, details go to server logs only; never log phone numbers, ID data or secrets; HTTPS only.

### 11.4 Error visibility

Add a basic error boundary on every dashboard page and server-side logging. (Optional: Sentry.) Provide `/api/health` that returns OK only if the sheet is reachable and headers are healthy — for the owner/developer, no private data in the response.

## 12. FILE UPLOADS (CLOUDINARY)

Uploads are required for tutors: **profile photo and Aadhaar copy are mandatory**; resume and qualification documents are optional. Files are stored in the client's **own Cloudinary account** (free tier is enough to start). Google Drive is **not** used for uploads.

- **Keys:** `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`. The secret stays on the server and is never sent to the browser.
- **Files must be private.** Upload with delivery type `authenticated` (never the default public type) into a folder like `tutors/<submission_key>/`. A permanent public URL must never exist for these files.
- **How a public upload works** (phone-friendly, avoids Vercel's ~4.5 MB request limit):
  1. The form asks `/api/public/upload-signature` for permission (rate-limited; needs the form's `submission_key`).
  2. The server returns a short-lived signature that only allows: authenticated type, formats `jpg`/`png`/`pdf`, the right folder.
  3. The browser uploads straight to Cloudinary and gets back a `public_id`.
  4. The form submits with the `public_id`s. Before saving the record, the server **checks with Cloudinary that each file exists, has an allowed format, and is 5 MB or less**; otherwise it rejects the submission and deletes the file.
- **Photos:** resize/compress in the browser before upload (max 1600 px, JPEG about 80%) so phone photos stay small. Aadhaar copy: image or PDF, 5 MB or less. Max 5 files per submission.
- **The sheet stores only the Cloudinary `public_id`** in the `*_file_id` columns (column names are kept as they are). Never store URLs.
- **Seeing files on the dashboard (important):** `/api/admin/files/[publicId]` checks the admin login, then returns a **signed URL that expires in about 10 minutes**. Use it to show:
  - the tutor's photo as a small avatar in lists and a large photo on the detail page and in Tutor Finder results;
  - the Aadhaar copy and other documents in a viewer (lightbox with zoom, and a PDF viewer) on the tutor detail page and inside the **verification panel**, side by side with the tutor's details, so the owner can compare the photo and document with the name and Aadhaar number. A fresh link is generated every time the admin opens a file, so the admin can view them anytime.
- **If an upload fails,** show an error and let the user retry. Never save a record that points to a missing file.
- **Cleanup:** deleting or anonymizing a record also deletes its files (Cloudinary destroy API). Settings → Data & Safety has a "Clean up unused uploads" button that lists files older than 24 hours not attached to any record, with a confirmation before deleting.
- **Admin can upload too:** on the tutor edit page, the owner can upload or replace the photo and Aadhaar copy (for Quick Add or walk-in tutors). A tutor without the required photo and Aadhaar copy cannot be set to `VERIFIED` (Section 15.2).

## 16. TUTOR FINDER (SMART MATCHING) — MOST IMPORTANT FEATURE

### 16.1 Flow

Owner opens Tutor Finder → picks a student (or arrives from a student's "Find tutors") → the page shows the student's requirement summary → the engine returns ranked tutors with explanations → the owner shortlists, contacts or assigns. **Never auto-assign.**

### 16.2 Hard filters (a tutor failing any is excluded)

1. Not archived.
2. `verification_status` allowed by policy `match_verification_policy`:
   - `VERIFIED_ONLY` (default)
   - `INCLUDE_UNDER_REVIEW`
   - `INCLUDE_PENDING` (includes PENDING and UNDER_REVIEW)
   - `REJECTED` and `BLACKLISTED` are **never** included.
3. `availability_status = ACTIVE`.
4. Teaches **at least one** of the student's required subjects (`subjects` or `secondary_subjects`).
5. Teaches the student's class.
6. Gender preference: if `MALE` → tutor gender `MALE`; if `FEMALE` → `FEMALE`; if `ANY` → everyone.
7. Mode: compatible if student `BOTH` or tutor `BOTH` or both equal.

A toggle "Include unverified tutors" on the page lets the owner relax rule 2 for this search. A toggle "Show excluded tutors and why" is useful for debugging.

### 16.3 Scoring (total possible = 100)

| Factor | Max | How |
|---|---:|---|
| Locality | 30 | Exact (student's locality is in the tutor's `localities` or equals `current_locality`) = 30. Nearby (a `LocalityLinks` neighbour) = 15 (only if `match_use_nearby` is on). Else 0. **Skipped for ONLINE-only requests.** |
| Subject | 25 | `25 × (required subjects the tutor covers ÷ total required subjects)` |
| Class | 10 | Already hard-filtered; award 10 |
| Board | 10 | 10 if student's board is in tutor `boards`, else 0. Skipped if the `boards` field is disabled |
| Fee | 10 | Tutor fee ≤ student budget → 10. Within `match_budget_tolerance_pct` (default 15%) above budget → 5. Else 0 |
| Timing | 5 | Student `FLEXIBLE` → 5. Tutor `available_timings` includes student's timing → 5. Else 0. Skipped if timings field disabled |
| Experience | 5 | `min(5, round(experience_years))` |
| Freshness | 5 | `last_confirmed_at` within 90 days → 5, else 0 |

**Final score = round(100 × points earned ÷ max points of the factors that apply).** This way, skipped/disabled factors don't unfairly lower scores, and weights always add up. Weights can be changed in Settings (`match_weights_json`); validate they are positive numbers.

Only show results with score ≥ `match_min_score` (default 30). Sort by score (desc), then verified-first, then more recently confirmed. Ties are fine.

### 16.4 Results display

Each result card/row: Photo, Name, Tutor ID, qualification, experience, subjects, classes, localities, expected fee, verification badge, availability badge, **active assignments count** (information only), last confirmed date (warn if > 90 days), **match score**, and **reason chips**:
✔ Subject matched · ✔ Class matched · ✔ Locality matched / ◐ Nearby locality · ✔ Within budget / ✖ Over budget by ₹X · ✔ Timing matched / ✖ Different timing · ✔ Board matched.
Mismatches must be shown clearly (red/amber chips). The score is a ranking aid; the owner can always override.

### 16.5 Actions

View tutor · Contact (WhatsApp, call) · **Shortlist** (creates an `Assignment` with `SHORTLISTED`, subjects chosen) · **Assign** (creates assignment, asks agreed fee) · **Compare** (select 2–4 tutors, side-by-side table) · **Exclude** (hides the tutor for this search session; to remember it permanently, mark the assignment `REJECTED`).
Multiple tutors can be shortlisted for one student.

### 16.6 Tests required for matching (Section 28)

Exact locality, nearby locality, no-locality-link, wrong subject, partial subject coverage, wrong class, over budget, gender preference, unverified, inactive, rejected, blacklisted, online-only student (locality skipped), disabled field (weights renormalized).

## 24. PRIVACY & DATA PROTECTION (India)

This system stores personal data of parents, **children**, and tutors. Treat it seriously. (Have the client confirm the final policy wording with a qualified advisor; the template is a starting point, not legal advice.)

- Consent checkbox on **both** public forms; store `consent_at` and `consent_version` (the version string of the privacy policy shown).
- Student form consent is given by the parent/guardian.
- Collect only what the bureau needs. Address proof and degree certificate are off by default; photo and Aadhaar are required and fully visible to the admin.
- Private file storage; admin-only access; edits logged.
- **Correction/deletion requests:** admin can Edit any record. Admin can **Anonymize** a student or tutor (confirmation dialog + reason): the app blanks all personal fields (names, phone, whatsapp, email, address, dob, school, notes, document IDs, introduction, etc.), deletes the stored Cloudinary files, sets `archived=TRUE`, keeps the ID and non-personal fields (class, subjects, locality zone, status) so reports remain valid, and logs `ANONYMIZED`. Assignments keep IDs only.
- **Retention:** setting `retention_months` (default 24). The Data & Safety page lists records older than that (LOST/archived students, REJECTED tutors) with a button to anonymize them in bulk. Nothing is deleted automatically.
- `docs/privacy-policy-template.md` and `docs/DATA-REQUESTS.md` (how the owner handles a deletion request step by step) must be delivered.

## 25. BACKUPS

Keep this simple for v1.

- **"Backup now"** button in Settings → Data & Safety: the app reads every tab and gives the owner one ZIP file (one CSV per tab) to download to their computer. It is logged as `EXPORT`. The ZIP contains personal data, so show a warning to store it safely.
- The app stores `last_backup_at` in Settings and shows a reminder banner on the Overview if the last backup is more than 7 days old.
- Google Sheets' own version history is a second safety net; mention it in `docs/ADMIN-GUIDE.md`.
- Files in Cloudinary are not in the ZIP (they live in Cloudinary); the sheet keeps their `public_id`s.
- Automatic scheduled cloud backups are a **later** add-on, not v1.
- Write `docs/BACKUP-RESTORE.md`: to restore, create a new blank sheet, share it with the service account, run `npm run setup-sheet`, import each CSV into its tab (keep the header row, and make sure phone columns stay plain text so the leading `+` is not lost), update `SPREADSHEET_ID`, redeploy, run `npm run check-sheet`. **Actually test one restore** before declaring this done.

## 26. DESIGN SYSTEM (PREMIUM, CLEAN, NOT A GENERIC TEMPLATE)

Establish this **before** building pages (Phase 0).

- **Feel:** calm, professional, minimal, information-dense but not crowded. Lots of whitespace, subtle borders, soft shadows, no heavy gradients or animations.
- **Font:** Inter (or similar) via `next/font`. Sizes: page title 24/600, section title 16/600, body 14/400, caption 12/400. Tabular numbers in tables/metrics.
- **Colors:** neutral gray scale for surfaces and text; brand colors from client config exposed as CSS variables (`--primary`, `--secondary`, `--accent`) so every client's brand applies everywhere. Light theme only in v1.
- **Spacing/radius:** 4px spacing scale; radius 8px (cards 12px); consistent page padding.
- **Status badge colors (use everywhere the same):**
  - Green: `VERIFIED`, `ACTIVE`, `PAID`, `CONVERTED`, `DONE`, `COMPLETED`
  - Amber: `PENDING`, `UNDER_REVIEW`, `NEW`, `SHORTLISTED`, `DEMO_SCHEDULED`, `PENDING` payment, `OPEN`
  - Blue: `CONTACTED`, `ACCEPTED`, `DEMO_COMPLETED`, `TUTOR_SHORTLISTED`
  - Gray: `INACTIVE`, `ON_HOLD`, `TEMPORARILY_UNAVAILABLE`, `CANCELLED`, archived
  - Red: `REJECTED`, `BLACKLISTED`, `FAILED`, `LOST`, overdue
- **Components to build once and reuse:** MetricCard, StatusBadge, DataTable (sortable, paginated, responsive), SearchInput (debounced), FilterDrawer, ConfirmDialog, DetailDrawer, FormField wrappers, EmptyState, Skeletons, PageHeader, MultiSelectChips.
- **Accessibility:** labels on all inputs, visible focus, keyboard navigable dialogs, color not the only status indicator (badges also have text).

## 28. TESTING (REQUIRED, NOT OPTIONAL)

Tools: **Vitest** (unit/integration), **Playwright** (critical end-to-end flows), in-memory repository adapter for fast tests, a separate **test spreadsheet** for adapter tests. Never run tests against a client's real sheet.

**Must-have tests:**

- *Student form:* valid submit; missing fields; bad phone; duplicate (flagged); idempotent retry; Sheets unavailable (shows error, no false success); record appears correctly in sheet.
- *Tutor form:* valid; multiple subjects/localities; bad phone; duplicate phone/email (no second record); upload type/size rejection; files are private (a direct Cloudinary URL without a signature fails; the admin's signed link works and expires); photo and Aadhaar copy are required; starts `PENDING`/`ACTIVE`.
- *Auth:* unauthorized access blocked on pages **and** API; login/logout; rate limit; expired/tampered cookie rejected.
- *Dashboard:* search; multi-filter; pagination; add/edit/archive; concurrent-edit rejection; verify (blocked when required fields or background check missing); reject/blacklist need reasons; feature-off route returns 404.
- *Matching:* the list in Section 16.6.
- *Assignments:* create; multiple tutors per student; valid/invalid transitions; history preserved; visible from student and tutor.
- *Sheets layer:* header missing/renamed; reordered columns; RAW writes keep `+91…` as text; values starting with `=` stay text; 429 retry; lock behavior.
- *Multi-client:* correct branding per `CLIENT_ID`; no sheet IDs/secrets in client bundle (search the built output); second client config loads independently.
- *Privacy:* anonymize clears personal fields and files; exports exclude sensitive fields and neutralize formulas.
- *Mobile:* forms and dashboard checked at 375px width.
